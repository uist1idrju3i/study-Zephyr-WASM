# ビルド検証 (2026-11-22)

## 環境

- Devin VM (Ubuntu Linux)
- nRF Connect SDK v3.4.2 (ワークスペース `~/ncs/v3.4.2`、ツールチェーンバンドル `197d1ad490`)
- Zephyr 4.4.2 (`/home/ubuntu/ncs/v3.4.2/zephyr`)
- ツールチェーン: Zephyr SDK 1.0.1 / GNU 14.3.0 `arm-zephyr-eabi`、west 1.5.0、CMake 4.2.1、dtc 1.5.0
- wasi-sdk-29.0 (`~/tools/wasi-sdk-29.0-x86_64-linux`、clang 21.1.4)
- WAMR: `wasm-micro-runtime` @ `06f6c8c6e64e75eee6b8a3ce06ac2c7d10d015bf`

## 検証 1: WAMR 本家 simple サンプルをそのままビルド

```sh
cd ~/ncs/v3.4.2
WASI_SDK_DIR=~/tools/wasi-sdk-29.0-x86_64-linux \
nrfutil sdk-manager toolchain launch --ncs-version v3.4.2 -- \
west build -b nrf54l15dk/nrf54l15/cpuapp -d /tmp/wamr-build-l15 \
  <WAMR>/product-mini/platforms/zephyr/simple -- -DZEPHYR_EXTRA_MODULES=<WAMR>
```

結果: 成功。WAMR が `Build as target THUMB` で自動構成され、`modules/wasm-micro-runtime/libwamr.a` が生成・リンクされました。

## 検証 2: このリポジトリの `app/` をビルド

```sh
cd ~/ncs/v3.4.2
WASI_SDK_DIR=~/tools/wasi-sdk-29.0-x86_64-linux \
nrfutil sdk-manager toolchain launch --ncs-version v3.4.2 -- \
west build -b nrf54l15dk/nrf54l15/cpuapp -d /tmp/szw-build \
  <このリポジトリ>/app -- -DZEPHYR_EXTRA_MODULES=<WAMR>
```

結果: 成功。

生成物: `app/zephyr/zephyr.elf`、`zephyr.hex`、`zephyr.bin` (sysbuild 配下 `app` イメージ)。

ビルド内の流れ: `wasm-app/main.c` が wasi-sdk でネストビルドされ `test_wasm.wasm` になり、`bin_to_header.cmake` で `test_wasm.h` に変換されて `src/main.c` に埋め込まれます。

## 観測した警告 (いずれも非致命)

- `Deprecated symbol NRF_PLATFORM_LUMOS is enabled` (NCS 側の sysbuild 既定)
- WAMR の `platform_internal.h` から net 系 Zephyr ヘッダーを引き込む際の `-Wundef` 警告多数 (WAMR 側が net ヘッダーを常時 include する構造が原因とみられる)
- cmsis_core_m.h の `CONFIG_ARMV8_1_M_MVEI` 未定義警告 (Zephyr 側ヘッダーの既存警告)

## 未検証の範囲

- 実機への書き込みと UART での実行出力 (DK がこの VM にないため)。`west flash` + シリアル確認は実機環境で要実施
- ランタイムの実行時動作 (WAMR が起動して WASM を実際に走らせたかどうか)。リンクとバイナリ生成までの確認です
- T2 マニフェスト経路 (`west init -l` + `west update`) の完全な実行。west.yml の内容は兄弟リポジトリ (study-Zephyr-rust) で実績のある同一構造で、`app/` 側のビルドは上記のとおり検証済みです
- AOT モジュール、fast インタプリタ、WASI fs/socket、ユーザーモード (拡張候補)

## 判明した制約

- `west build` はワークスペース内で実行する必要がある (workspace 外の `west` には `build` コマンドがない)
- wasi-sdk-34.0 (現行最新) には `share/cmake/wasi-sdk.cmake` がなく、WAMR の `FindWASISDK.cmake` では検出できない。wasi-sdk-29〜33 を使う
- `nrfutil sdk-manager toolchain launch` は `ZEPHYR_BASE` を設定しない
